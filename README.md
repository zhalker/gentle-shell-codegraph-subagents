# @zhalker/gentle-shell-codegraph-subagents

Pi package that keeps CodeGraph reachable, and actually used, by gentle-shell subagents. Install it once: gentle-shell itself ships the CodeGraph MCP tool in its agent assets, and this package keeps the project index synced and its daemon warm, warns when that shipped tool is not exposed, and appends one CodeGraph rule to the system prompt of every agent that can call it. It never edits an agent file.

Upstream issue: Gentleman-Programming/gentle-shell#2804. License: MIT.

## Features

- **CodeGraph comes with the agents.** gentle-shell ships `mcp__codegraph__codegraph_explore` in the explorer, verifier, worker, fix agent and both judges itself, so this package does not touch `~/.pi/agent/agents/*.md` or `~/.pi/agent/subagents/*.md`: gentle-pi keeps managing and upgrading them. An older gentle-shell whose agent assets lack the tool is not patched by editing the file; upgrade gentle-shell instead.
- **Agent files an older version froze go back to gentle-pi.** A file this package froze in a published version (0.1.0 to 0.6.0) is swapped out at load, gentle-pi recreates it from its own assets in the same startup with the model routing you saved, and the leftover copy is removed as soon as the file is back. If gentle-pi does not recreate it, the copy is restored byte for byte (on the first prompt of that session, never at a load) and the file is left alone. Nothing is deleted, no second backup is written, and the existing `.pre-codegraph-subagents.bak` is never modified.
- **The MCP tool is really there.** The MCP exposure still decides whether the shipped `codegraph_explore` tool is visible to subagents. The package only reads that configuration: if the CodeGraph server is missing, Pi tells you at startup, and if direct subagent access is unavailable you get a warning. `mcp.json` is never rewritten, so your settings are always preserved.
- **One rule, in the prompt of every agent that can use CodeGraph.** The extension appends a `## CodeGraph` section to the system prompt of the primary session and of every subagent whose tools include the native `codegraph` tool or the MCP explore tool: call CodeGraph before symbol searches with `rg` or `grep` and before broad `find`, write only the current workspace's index, and fall back to `read`, `grep` and `find` only when CodeGraph is unavailable or fails. Reviewers hold neither tool and get nothing. When the checkout has an index, one line inside the section says so. The section is appended after the harness's own text, never returned as a replacement prompt, and skipped when its heading is already there.
- **A fresh index at every session start.** Every new session syncs the index in the background, or creates it for a git project with a known manifest (`package.json`, `composer.json`, `go.mod`, `Cargo.toml` and more). A linked git worktree gets its own index: it is seeded from the main checkout's index when one exists (a file copy plus a sync, ~65% faster than a full init in the reference probe) and initialised the normal way when it does not, so a worktree always answers with its own tree, never with the main checkout's files. Your session never waits for any of it. A subagent child handed a worktree as its `workspace_root` does the same in the background: an unindexed worktree gets seeded (or initialised) while the child starts, and a worktree that already has an index — or any ordinary child directory — is left to the parent's session as before.
- **A native `codegraph init` is observed, never replaced.** After a successful native `codegraph init` call the extension asks its own coordination for one sync of that checkout and appends the outcome to the tool's result: `completed`, `pending` or `failed`. A failed init keeps its original error and triggers no sync, and the hook never makes the call fail. A pending or failed request is never worded as a synced index.
- **Every index write is coordinated.** Startup, worktree seeding, compaction and the post-init sync all go through the package's per-project index lock and, for syncs, the per-project lease: an uncoordinated `init`/`sync` is never started, and a request that cannot be coordinated is reported (`queued`, `unavailable`, or a warned `failed`), not silently dropped.
- **Read-only roles stay read-only.** verify and the judges, recognised without an agent name from the tool list gentle-pi requested for the child, never initiate an `init` or a `sync`, not even in an unindexed worktree they were handed. Navigation is not proof: a CodeGraph answer is a hint, and the package never calls a queued or failed operation a current index.
- **Synced again after each compaction.** A long session compacts many times; each compaction of a parent session requests one quiet background sync of the project's index: never an init, never a message. Sessions of the same user coordinate through the temp folder, so two package-started syncs of one project never run at the same time, and requests that arrive during a sync become one follow-up of it.
- **Warm from the first call, on the checkout's own daemon.** After syncing, the extension warms the daemon of the checkout it acted on, reusing a live registered daemon before spawning anything, so the first real query is fast (~70 ms instead of ~650 ms locally). A worktree is its own root with its own daemon; the parent checkout's daemon is never used for a child's. An MCP server entry is never taken as evidence that a daemon is reachable, and the package never rewrites the MCP configuration, never registers a tool of its own and never kills a daemon it did not start.
- **Built for Windows and network shares.** A mapped drive (`Y:\`) and its UNC path (`\\server\share`) are the same project, so no duplicate daemons. CodeGraph runs correctly on UNC folders, and any folder name reaches it intact (`%`, `&`, `^`, spaces).
- **One reminder, only if the first move is a search.** On the first `grep`, `find`, `ls` or shell command that searches, a session that can call CodeGraph and has not called it yet gets one short message naming the rule. It never blocks the call, never fires twice in a session, and the budget starts over after a compaction. The primary session and read-only explorer-style children are reminded; a child that writes files is not.
- **No skill of its own.** The package ships no skill and sends no skill reminder: the rule rides the system prompt, so there is nothing for Pi to select or collide with.
- **Safe to install, easy to undo.** It writes no agent file and no `mcp.json`; every index write is coordinated through a per-project lock. The repair of frozen files only renames: a repaired file waits as `<file>.codegraph-repair-pending` until gentle-pi recreates it.
- **Diagnosable.** Every compaction sync writes its outcome and duration to `~/.pi/agent/codegraph-subagents/sync.log`.

## The compatibility layer

gentle-shell is not modified: this package is the compatibility layer, and it only uses what the Pi extension API and the CodeGraph CLI already offer.

- **No tool of its own, no shadowing, no load order.** The package registers no tool named `codegraph`, never wraps or overrides another extension's tool, and never depends on which extension loads first. The native `codegraph` tool keeps working exactly as its owner wrote it.
- **Observed, not replaced.** A native `codegraph init` is followed through Pi's `tool_result` hook, which can append to a tool's result after it ran. The append is bounded to 10 s: if the coordinated sync has not come back by then, the result says `pending`, and the request stays recorded until a run serves it. Pi catches a throwing handler, so the hook cannot make the tool call fail.
- **Create-or-sync, coordinated.** `.codegraph` present means `sync`; a fresh git project with a known manifest means `init -y`; a linked worktree without an index is seeded from the main checkout and then synced; anything else is left alone. Every one of those writes holds the per-project index lock, and every sync also goes through the per-project lease, so no two package-started writes of one project overlap.
- **Per checkout, MCP optional.** The daemon is resolved for the checkout the extension is acting on (a worktree included), from that checkout's CodeGraph daemon registry. MCP availability and daemon reachability are independent: an `mcp.json` entry does not start or prove a daemon, and a live daemon needs no MCP entry. The package never rewrites `mcp.json` and never stops a daemon it did not start.
- **Honest reporting.** The session notices, the appended tool-result line and the two log files distinguish `completed`, `pending`, `skipped` and `failed`, and only a run that really came back is called synced.

See [docs/compatibility-layer.md](docs/compatibility-layer.md) for the exact contract and the cases it does not cover.

## Why

Gentle-shell subagents often skip CodeGraph and fall back to recursive grep: the MCP server hides the tool from them, or the model decides there is no index because `.codegraph/` is git-ignored and invisible to Pi's `find` and `grep` tools, `fd` and `rg`. On network shares the CodeGraph file watcher does not work either, so the index goes stale. gentle-shell now ships the tool in its own agent assets; this package keeps the index current and its daemon warm at session start, warns when the shipped tool is hidden, and puts the rule in every agent's prompt so the model reaches for CodeGraph instead of recursive grep.

## Requirements

- Pi with gentle-pi (gentle-shell subagents). Tested with Pi 1.4.0-1.5.0.
- The CodeGraph CLI on Pi's `PATH`, and the `codegraph` MCP server configured.
- Node 24.

## Index and worktrees

Every session keeps the project's CodeGraph index current on its own; a linked git worktree gets one of its own too. The decision per directory, in order:

1. Index present → quiet `codegraph sync` (startup, resume, fork and after each compaction).
2. Linked git worktree without an index → the worktree's own index is **seeded** from the main checkout's index when that exists: a copy of its `codegraph.db` while nobody is writing it, then one `codegraph sync` in the worktree so the copy matches this tree. The worktree never shares the main checkout's index. When the main checkout has no index (or an init is writing it), the worktree falls back to the plain init below; two sessions starting at once in the same worktree seed it only once.
3. Fresh git project with a known manifest → `codegraph init -y`.
4. Anything else → nothing is created.

The same decision runs for a subagent child whose `workspace_root` is a worktree: a child never touches the index of the directory it shares with its parent, but an unindexed worktree handed to it gets the seeding or init above, in the background, under the same locks. This is what makes orchestrator-created worktrees usable without opening a session in them: the first child brings its own index up, later ones just use it. On top of that, every parent session seeds its repository's unindexed linked worktrees at startup (one quiet `git worktree list`, then the same seeding decision per worktree), and subscribes to gentle-pi's worktree-registry event (`gentle-pi:session-worktree-changed` on Pi's shared extension bus) so a worktree registered mid-session is seeded the moment it joins, not at the next scan. The subscription is best-effort and defensive — if gentle-pi renames its internal channel, seeding degrades to the startup scan, never breaks the session; the ask to stabilize that channel upstream is drafted in `zh_lia/issues/gentle-shell-worktree-registry-event.md`.

A seeded index costs a copy plus one sync (~65% faster than a full init in the reference probe on this repository) and every worktree's database lives inside that worktree, so removing the worktree removes its index with it.

## Install

```
pi install npm:@zhalker/gentle-shell-codegraph-subagents
```

Changes apply on the next session start. Reinstalling, or running `gentle-ai sync` again, is corrected the same way on the following start.

## Uninstall

Remove the package. A frozen file a repair had just swapped out waits as `*.codegraph-repair-pending`: rename it back under its own name. Backups (`*.pre-codegraph-subagents.bak`) were written only by versions up to 0.9.x; when one exists, copy it over its original if you want that file back.

## How it works

No agent file is edited: gentle-shell ships `mcp__codegraph__codegraph_explore` in the explorer, verifier, worker, fix agent and both judges, and gentle-pi keeps managing and upgrading those files. The `review-*` agents stay without CodeGraph, as shipped. Any local edit would make gentle-pi drop an agent file from `~/.pi/agent/gentle-ai/managed-assets.json` at the next session start and stop refreshing it on upgrades; that is exactly why this package no longer writes one.

The one agent-file operation left is a repair, and it only renames. In `~/.pi/agent/agents/` only, and outside subagent children, it happens at extension load, before gentle-pi's own startup install: a file a published version of this package froze is repaired, so it is not stuck on an old body for good. A file qualifies only when all of these hold:

- gentle-pi is installed where Pi keeps it (`~/.pi/agent/npm/node_modules/gentle-pi`, `package.json` name `gentle-pi`) and its `assets/migrations/agent-body-history.json` is readable. Otherwise nothing is touched and the reason is shown.
- Its `<file>.pre-codegraph-subagents.bak` exists, and that backup without gentle-ai's blocks is a body gentle-pi itself ships.
- Without its `model:`/`thinking:` lines, the file is exactly what the normalizer of 0.1.0 or 0.2.0-0.6.0 wrote from that backup, or its body (after a trailing `<!-- codegraph-workflow:worker -->` line) is a body gentle-pi ships and its frontmatter is exactly what that normalizer writes from the agent the installed gentle-pi ships. A frontmatter edited by hand (tools, description) is never repaired. The frozen normalizers are recognised, never run: nothing here writes an agent file.
- Its `model:`/`thinking:` lines are absent or equal the entry `~/.pi/gentle-ai/models.json` holds for that agent, so the recreated file gets the same routing.
- `~/.pi/agent/gentle-ai/managed-assets.json` does not list the file with its current content: gentle-pi still manages it, so it was never frozen.
- `GENTLE_PI_AGENT_HOME`, when it is set, names this same agent directory. gentle-pi resolves its agent home as `GENTLE_PI_AGENT_HOME`, then `PI_CODING_AGENT_DIR`, then `~/.pi/agent`; if the first one points somewhere else, gentle-pi recreates its agents there and nothing here is touched, with that reason shown.

A qualifying file is renamed to `<file>.codegraph-repair-pending`, so gentle-pi's startup install finds it missing and recreates it from its assets, with the routing from `models.json`, and manages it again. The swap is settled in two steps. At the next load, a pending copy whose file is back is removed, and one whose file is still missing is left alone: at that point this session's own startup install has not run yet, so a missing file proves nothing. On the first prompt of the parent session, after that session's install had its chance, a pending copy whose file is still missing is restored byte for byte and recorded in `~/.pi/agent/codegraph-subagents/repair-state.json`, so that file is not tried again while it and its backup are unchanged. Two sessions starting at once cannot lose a file: a name is only created when it is free and a file that already exists is never overwritten, and no load ever rolls a swap back. Every repaired, settled and rolled-back file is shown at startup; a file left alone is not, since it needs nothing from you.

The rule is one system-prompt section, added inside `before_agent_start`: the extension appends it to `event.systemPromptOptions.appendSystemPrompt`, after whatever text the harness put there, and never returns a replacement system prompt (a replacement would erase the harness's own instructions). The `## CodeGraph` heading is the identity of the block, so a session that already carries it gets nothing added. The gate is the session's own tool list: the selected tools plus, in a subagent child, the list gentle-pi requested for it. A session holding neither the native `codegraph` tool nor `mcp__codegraph__codegraph_explore` gets no section, which is how the reviewers stay out. When `.codegraph/codegraph.db` is found at or above the session's directory, one line inside the section says the workspace has an index, so no separate notice is sent and no message has to be re-sent after a compaction. The section is fixed text: it cannot grow with the session.

In `mcp.json`: nothing is written. The package only reads the effective exposure of `codegraph_explore` (the global file, a trusted project's override, and servers registered by extensions) to decide whether the shipped tool is visible. At session start Pi warns when the CodeGraph MCP server is not configured, without creating it, or when direct subagent access may be unavailable; it also warns if a hidden server has an explicit direct explore exception, which Pi can still expose. That warning is the whole interaction: if you want direct access, set it yourself, and a configuration change may require a reload before Pi uses it.

The reminder is decided in the `tool_call` hook: the session records every native `codegraph` or MCP explore call, and the first `grep`, `find`, `ls` or shell command that searches, made before any of them, sends one short message through `pi.sendMessage` naming the rule. It is a message, not a veto: the call runs, nothing throws, and the budget is in memory, so a compaction is the only thing that starts it over. Only the primary session and a read-only, explorer-style child are candidates; a child whose requested tool list contains a file-writing tool never is. The shell check is a word match on the command line (`grep`, `rg`, `find`, `fd`, `ls`, `dir`, `Get-ChildItem` and similar), so an unusual command can be missed, and the reminder is advisory either way.

In the directory where Pi starts, a new session also looks after the CodeGraph index, in the background (the session never waits for it):

- If `.codegraph/` exists, it runs `codegraph sync`. The CodeGraph file watcher does not work on SMB mounts, so without this the index stays as it was.
- If the directory is a linked git worktree without `.codegraph/` and the main checkout has an index, it seeds the worktree's own index: it copies the main checkout's `codegraph.db` (only while nobody is writing it, and never leaving a half-built index behind) and runs `codegraph sync` in the worktree, so the seeded index matches the worktree's tree. The worktree never shares the main checkout's index: each tree answers with its own files. Two sessions starting at once in the same worktree seed it only once.
- If there is no `.codegraph/`, but there is a `.git` and one of `composer.json`, `package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `Gemfile`, `pom.xml`, `build.gradle` or `build.gradle.kts`, it runs `codegraph init -y`. In any other directory nothing is created.
- When there is an index (existing, or just created), it then warms the project's CodeGraph daemon: a short MCP client runs one small `codegraph_explore` and disconnects, and the daemon stays up for as long as your session keeps it. The first real call of the orchestrator and of every subagent is then fast (locally 620-650 ms cold against ~70 ms warm). 
- `codegraph` always runs from the temp folder with the project as an argument (`sync -q <project>`, `init -y <project>`, `serve --mcp -p <project>`), never with the project as its working directory: on Windows, cmd.exe does not accept a UNC working directory and would run the command in the Windows directory. The path reaches `codegraph` literally, whatever characters the folder name has (`%`, `&`, `^`, spaces). It is spelled as the project's live daemon registered it (a record counts as live only while its process runs and its socket is still present), because CodeGraph starts one daemon per spelling. A mapped drive (`Y:\...`) and the UNC path behind it (`\\server\share\...`), and two letter cases of one path, are the same project.
- Pi shows a notice when each step starts ("syncing the CodeGraph index...", "creating the CodeGraph index of this project...", "seeding this worktree's CodeGraph index from the main repo's index...", "warming up CodeGraph...") and another when it ends ("CodeGraph index synced", "CodeGraph index created", "CodeGraph index seeded from the main repo and synced", "CodeGraph ready"), a warning if it failed or if the sync coordination could not be used at all, or an informational line when it left the run to another session or while its request waits for the index to be free.
- A per-project lock in the user's temp folder orders the package's own index writers: `codegraph init` and `codegraph sync` of one project take it in turn, so neither starts in the middle of the other. A sync takes the lock for its whole run and records the `codegraph` process it started, so an init cannot begin mid-sync and a session killed mid-sync leaves a lock that still speaks for that process. A session that finds an init holding it skips init, sync and warm-up. When a session exits during init, the package also checks CodeGraph's writer lock. On Windows it conservatively holds the package lock for 60 seconds after spawning the shell, covering the period before CodeGraph writes its own lock. Locks are treated as stale after 11 minutes.
- A separate per-project lease in the same temp folder orders the package's own syncs, startup and compaction alike: a session that finds another one syncing records one pending request on disk and that session serves it with a single follow-up run, so two package-started syncs of one project never run at the same time. A request is only marked as served after the run that started after it has finished, so a session killed mid-sync loses no demand and a session is only told `coalesced` when a run really completed; a request that has not been served yet is reported as `queued` and stays on disk for the next sync. The lease names the session and the `codegraph` process it started, and is restamped before every run: a sync that outlives a killed session keeps the other sessions waiting until it ends, and nothing is killed to get there. When the lease cannot be created or read at all, the package starts no sync (it does not fall back to an uncoordinated one). A session whose startup sync was coalesced still warms the daemon, because the index exists.
- Subagent children and `/reload` do nothing; startup, new, resume and fork do. A read-only child (verify, the judges) never does any of it, not even in a worktree: `verify` runs commands but writes no file, and the package starts no index write for that role.
- A native `codegraph init` the model runs itself is observed afterwards: one coordinated sync of that checkout is requested and its outcome (`completed`, `pending`, `failed`) is appended to the tool's result. A failed init keeps its own error and triggers nothing. The hook only sees the native `codegraph` tool, not `codegraph init` typed into `bash`. The final outcome of a request that was still pending goes to `sync.log`.

After each compaction of a parent session (not of a subagent child, which shares its parent's project) the extension requests one quiet `codegraph sync` in the background, but only when the directory where Pi starts already has an index: a compaction never creates one, never makes the session wait and never shows a message. If the index is being initialised at that moment the request is kept and served once the init ends, instead of being dropped. The outcome — `synced`, `failed`, `coalesced`, `queued` (recorded, not served yet) or a `skipped-` reason (`skipped-no-index`, `skipped-child`, `skipped-coordination-unavailable`) — is appended to `~/.pi/agent/codegraph-subagents/sync.log`, so a sync that failed without telling anyone can still be diagnosed. The coordination above only orders the package's own runs between local sessions of this user that share the temp folder: it cannot order the CodeGraph CLI, a daemon, a git hook, another tool or another machine, and neither a successful exit code nor a warm daemon makes the index current for a read. See [docs/known-limits.md](docs/known-limits.md).

The only files it writes are its own state under `~/.pi/agent/codegraph-subagents/`: the sync log, the repair record and the pending swap names.
