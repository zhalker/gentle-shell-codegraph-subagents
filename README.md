# @zhalker/gentle-shell-codegraph-subagents

Pi package that keeps CodeGraph reachable, and actually used, by gentle-shell subagents. Install it once: on every session start it fixes the agents' tool lists and the CodeGraph MCP exposure, keeps the project index synced and its daemon warm, and hands the explorer subagent CodeGraph's answer before it even starts.

Upstream issue: Gentleman-Programming/gentle-shell#2804. License: MIT.

## Features

- **CodeGraph in every subagent that should have it.** On each session start the explorer, verifier, worker and judge agents get `mcp__codegraph__codegraph_explore` in their tool list. An agent file is edited only when gentle-ai already left its CodeGraph blocks in it: those files are frozen for gentle-pi anyway, so the blocks and the dead proxy entries are removed there and nowhere else. A file gentle-ai never touched is left byte for byte, so gentle-pi keeps updating it. Review agents never get CodeGraph.
- **Agent files an older version froze go back to gentle-pi.** A file this package froze in a published version (0.1.0 to 0.6.0) is swapped out at load, gentle-pi recreates it from its own assets in the same startup with the model routing you saved, and the leftover copy is removed as soon as the file is back. If gentle-pi does not recreate it, the copy is restored byte for byte (on the first prompt of that session, never at a load) and the file is left alone. Nothing is deleted, no second backup is written, and the existing `.pre-codegraph-subagents.bak` is never modified.
- **The MCP tool is really there.** `codegraph_explore` is exposed directly to subagents in `mcp.json`, keeping every other setting you made. If the CodeGraph server is missing, Pi tells you at startup.
- **The model knows the index exists.** On the first prompt of a session, and of every subagent that holds a CodeGraph tool, the extension states that the project has an index and names the exact tools to call first. Models no longer "check" with Pi's find and grep tools, fd or rg, which respect `.gitignore` and never show the git-ignored `.codegraph/`. It comes back after each compaction, which would otherwise summarize it away, and on screen it is one short line that expands to the full text.
- **The explorer starts with an answer.** Before its first model call, the explorer subagent receives CodeGraph's answer for its task straight from the running daemon: about 75 ms on a local disk, typically 1-2 s on a network share.
- **A fresh index at every session start.** Every new session syncs the index in the background, or creates it for a git project with a known manifest (`package.json`, `composer.json`, `go.mod`, `Cargo.toml` and more). A linked git worktree gets its own index: it is seeded from the main checkout's index when one exists (a file copy plus a sync, ~65% faster than a full init in the reference probe) and initialised the normal way when it does not, so a worktree always answers with its own tree, never with the main checkout's files. Your session never waits for any of it. A subagent child handed a worktree as its `workspace_root` does the same in the background: an unindexed worktree gets seeded (or initialised) while the child starts, and a worktree that already has an index — or any ordinary child directory — is left to the parent's session as before.
- **Synced again after each compaction.** A long session compacts many times; each compaction of a parent session requests one quiet background sync of the project's index: never an init, never a message. Sessions of the same user coordinate through the temp folder, so two package-started syncs of one project never run at the same time, and requests that arrive during a sync become one follow-up of it.
- **Warm from the first call.** After syncing, the extension warms the project's CodeGraph daemon, so the first real query is fast (~70 ms instead of ~650 ms locally). When an explorer finds no daemon, it starts one in the background for the next one.
- **Built for Windows and network shares.** A mapped drive (`Y:\`) and its UNC path (`\\server\share`) are the same project, so no duplicate daemons. CodeGraph runs correctly on UNC folders, and any folder name reaches it intact (`%`, `&`, `^`, spaces).
- **A CodeGraph workflow skill included.** The packaged `codegraph-workflow` skill tells the model when to use CodeGraph and when a plain read or grep is better, with a reminder on the first prompt of the session and of worker subagents.
- **Safe to install, easy to undo.** It edits only the agent definitions in `~/.pi/agent/agents/` and `~/.pi/agent/subagents/` and the `codegraph` entry of `~/.pi/agent/mcp.json`. Each file is backed up once as `<file>.pre-codegraph-subagents.bak` before its first change, nothing is rewritten when everything is already right, and concurrent sessions coordinate through a per-project lock. The repair of frozen files only renames: a repaired file waits as `<file>.codegraph-repair-pending` until gentle-pi recreates it.
- **Diagnosable.** Every explorer prefetch writes its outcome and duration to `~/.pi/agent/codegraph-subagents/prefetch.log`, and every compaction sync writes its outcome to `~/.pi/agent/codegraph-subagents/sync.log`.

## Why

Gentle-shell subagents often skip CodeGraph and fall back to recursive grep: their tool lists lack it, the MCP server hides it from them, or the model decides there is no index because `.codegraph/` is git-ignored and invisible to Pi's `find` and `grep` tools, `fd` and `rg`. On network shares the CodeGraph file watcher does not work either, so the index goes stale. This package fixes each of those at session start.

## Requirements

- Pi with gentle-pi (gentle-shell subagents). Tested with Pi 1.4.0-1.5.0.
- The CodeGraph CLI on Pi's `PATH`, and the `codegraph` MCP server configured.
- Node 24.

## Index and worktrees

Every session keeps the project's CodeGraph index current on its own; a linked git worktree gets one of its own too. The decision per directory, in order:

1. Index present → quiet `codegraph sync` (startup, resume, fork and after each compaction).
2. Linked git worktree without an index → the worktree's own index is **seeded** from the main checkout's index when that exists: a copy of its `codegraph.db` while nobody is writing it, then one `codegraph sync` in the worktree so the copy matches this tree. The worktree never shares the main checkout's index. When the main checkout has no index (or an init is writing it), the worktree falls back to the plain init below; two sessions starting at once in the same worktree seed it only once.
3. Fresh git project with a known manifest → `codegraph init -y`.
4. Anything else → nothing is created.

The same decision runs for a subagent child whose `workspace_root` is a worktree: a child never touches the index of the directory it shares with its parent, but an unindexed worktree handed to it gets the seeding or init above, in the background, under the same locks. This is what makes orchestrator-created worktrees usable without opening a session in them: the first child brings its own index up, later ones just use it. On top of that, every parent session seeds its repository's unindexed linked worktrees at startup (one quiet `git worktree list`, then the same seeding decision per worktree), so the index usually exists before the first child is even handed the worktree; the child-side seeding stays as the fallback that guarantees it either way.

A seeded index costs a copy plus one sync (~65% faster than a full init in the reference probe on this repository) and every worktree's database lives inside that worktree, so removing the worktree removes its index with it.

## Install

```
pi install npm:@zhalker/gentle-shell-codegraph-subagents
```

Changes apply on the next session start. Reinstalling, or running `gentle-ai sync` again, is corrected the same way on the following start.

## Uninstall

Remove the package, then copy each `*.pre-codegraph-subagents.bak` over its original if you want the previous files back. A frozen file a repair had just swapped out waits as `*.codegraph-repair-pending`: rename it back under its own name.

## How it works

In `~/.pi/agent/agents/` and `~/.pi/agent/subagents/` (or `$PI_CODING_AGENT_DIR`):

- Leaves a file with no gentle-ai marker blocks byte for byte untouched. Any local edit makes gentle-pi drop an agent file from `~/.pi/agent/gentle-ai/managed-assets.json` at the next session start and stop refreshing it on upgrades, so an agent that gentle-ai never touched keeps being updated.
- In a file that carries gentle-ai's blocks (that file is already frozen), removes the blocks between `<!-- gentle-ai:pi-codegraph-tool -->` / `<!-- gentle-ai:pi-codegraph-guidance -->` and `<!-- /gentle-ai:pi-codegraph -->`.
- In the same frozen file, removes the dead `mcp` entry (the retired `pi-mcp-adapter` proxy) and the `"*": false` entry from the `tools:` list.
- Adds `mcp__codegraph__codegraph_explore` to `gentle-ai-explore`, `gentle-ai-verify`, `gentle-ai-worker`, `jd-fix-agent`, `jd-judge-a` and `jd-judge-b` when it is missing. Everything else in `tools:` stays, including a `codegraph` extension tool, and the explorer keeps its own instruction lines.
- Writes no routing marker into any file.
- Leaves the `review-*` agents without CodeGraph.

In `~/.pi/agent/agents/` only, and outside subagent children, one more thing happens at extension load, before gentle-pi's own startup install: a file a published version of this package froze is repaired, so it is not stuck on a 4.6.0 (or older) body for good. A file qualifies only when all of these hold:

- gentle-pi is installed where Pi keeps it (`~/.pi/agent/npm/node_modules/gentle-pi`, `package.json` name `gentle-pi`) and its `assets/migrations/agent-body-history.json` is readable. Otherwise nothing is touched and the reason is shown.
- Its `<file>.pre-codegraph-subagents.bak` exists, and that backup without gentle-ai's blocks is a body gentle-pi itself ships.
- Without its `model:`/`thinking:` lines, the file is exactly what the normalizer of 0.1.0 or 0.2.0-0.6.0 wrote from that backup, or its body (after a trailing `<!-- codegraph-workflow:worker -->` line) is a body gentle-pi ships and its frontmatter is exactly what that normalizer writes from the agent the installed gentle-pi ships. A frontmatter edited by hand (tools, description) is never repaired.
- Its `model:`/`thinking:` lines are absent or equal the entry `~/.pi/gentle-ai/models.json` holds for that agent, so the recreated file gets the same routing.
- `~/.pi/agent/gentle-ai/managed-assets.json` does not list the file with its current content: gentle-pi still manages it, so it was never frozen.
- `GENTLE_PI_AGENT_HOME`, when it is set, names this same agent directory. gentle-pi resolves its agent home as `GENTLE_PI_AGENT_HOME`, then `PI_CODING_AGENT_DIR`, then `~/.pi/agent`; if the first one points somewhere else, gentle-pi recreates its agents there and nothing here is touched, with that reason shown.

A qualifying file is renamed to `<file>.codegraph-repair-pending`, so gentle-pi's startup install finds it missing and recreates it from its assets, with the routing from `models.json`, and manages it again. The swap is settled in two steps. At the next load, a pending copy whose file is back is removed, and one whose file is still missing is left alone: at that point this session's own startup install has not run yet, so a missing file proves nothing. On the first prompt of the parent session, after that session's install had its chance, a pending copy whose file is still missing is restored byte for byte and recorded in `~/.pi/agent/codegraph-subagents/repair-state.json`, so that file is not tried again while it and its backup are unchanged. Two sessions starting at once cannot lose a file: a name is only created when it is free and a file that already exists is never overwritten, and no load ever rolls a swap back. Every repaired, settled and rolled-back file is shown at startup; a file left alone is not, since it needs nothing from you.

The package also provides the `codegraph-workflow` skill. When Pi loads this packaged skill, the extension adds a reminder before the first user prompt of the parent session and the first prompt of `gentle-ai-worker` children. It does not add the reminder to other children. A worker child is recognised without a marker in its agent file: gentle-pi runs an agent body over 1000 bytes as a file passed after `--append-system-prompt`, inside a `gentle-pi-subagent-gentle-ai-worker-*` folder, so the extension reads its own command line; a worker file edited by an older version of this package still counts through the marker it carries. Pi handles skill name collisions; if Pi selects a different skill with that name, the extension does not direct the model to it as if it were the packaged skill. A local package is discovered in place rather than copied to the user's skills directory.

In `mcp.json`: selects `"direct"` for `codegraph_explore` under `toolExposure`, without changing the server-wide exposure. Explicit tool settings (including matching patterns), disabled servers, and hidden servers are preserved. At session start Pi warns when the CodeGraph MCP server is not configured, without creating it, or when direct subagent access may be unavailable; it also warns if a hidden server has an explicit direct explore exception, which Pi can still expose. Trusted project MCP configuration and servers registered by extensions are considered. A configuration change may require a reload before Pi uses it.

In a subagent that only reads and holds `mcp__codegraph__codegraph_explore` (the explorer), a `before_agent_start` hook also runs `codegraph_explore` for its task once before the first model call and hands the output to the model as a message, bounded to 10 s and 12,000 characters. It asks the project's running CodeGraph daemon directly (the same text as the CLI, locally ~75 ms against ~590 ms). When there is no daemon it adds nothing at once and starts the project's warm-up in the background, so the next explorer finds the daemon warm; it never runs `codegraph explore` and never waits for a daemon it would have to start. If the project has no `.codegraph/` index, the package's init lock is held, or the daemon has nothing to say, nothing is added and the run continues as before.

On the first prompt of a session, and of a child that holds a CodeGraph tool, the extension also states that the project's index exists and names the CodeGraph tools to call first, because a model on its own checks with Pi's find and grep tools, fd or rg, which respect `.gitignore` and never show the git-ignored `.codegraph/`. The main session sees this notice as one short line (`ctrl+o` expands it to the full text the model received); children get it hidden. After a compaction the summary usually drops the notice and the skill reminder, so the first user prompt after it carries them again, once and always hidden; while they are still in what the model sees they are not repeated. Every explorer pre-fetch appends `time, outcome, duration, directory` to `~/.pi/agent/codegraph-subagents/prefetch.log` (outcomes: `ok`, `empty`, `daemon-timeout`, `daemon-error`, `skipped-no-daemon`, `skipped-init-running`; control characters in the directory are written as `?`), so a pre-fetch that silently produced nothing can still be diagnosed.

In the directory where Pi starts, a new session also looks after the CodeGraph index, in the background (the session never waits for it):

- If `.codegraph/` exists, it runs `codegraph sync`. The CodeGraph file watcher does not work on SMB mounts, so without this the index stays as it was.
- If the directory is a linked git worktree without `.codegraph/` and the main checkout has an index, it seeds the worktree's own index: it copies the main checkout's `codegraph.db` (only while nobody is writing it, and never leaving a half-built index behind) and runs `codegraph sync` in the worktree, so the seeded index matches the worktree's tree. The worktree never shares the main checkout's index: each tree answers with its own files. Two sessions starting at once in the same worktree seed it only once.
- If there is no `.codegraph/`, but there is a `.git` and one of `composer.json`, `package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `Gemfile`, `pom.xml`, `build.gradle` or `build.gradle.kts`, it runs `codegraph init -y`. In any other directory nothing is created.
- When there is an index (existing, or just created), it then warms the project's CodeGraph daemon: a short MCP client runs one small `codegraph_explore` and disconnects, and the daemon stays up for as long as your session keeps it. The first real call of the orchestrator and of every subagent is then fast (locally 620-650 ms cold against ~70 ms warm). The explorer's pre-fetch asks that same daemon, so it gets the same speed-up.
- `codegraph` always runs from the temp folder with the project as an argument (`sync -q <project>`, `init -y <project>`, `serve --mcp -p <project>`), never with the project as its working directory: on Windows, cmd.exe does not accept a UNC working directory and would run the command in the Windows directory. The path reaches `codegraph` literally, whatever characters the folder name has (`%`, `&`, `^`, spaces). It is spelled as the project's live daemon registered it (a record counts as live only while its process runs and its socket is still present), because CodeGraph starts one daemon per spelling. A mapped drive (`Y:\...`) and the UNC path behind it (`\\server\share\...`), and two letter cases of one path, are the same project.
- Pi shows a notice when each step starts ("syncing the CodeGraph index...", "creating the CodeGraph index of this project...", "seeding this worktree's CodeGraph index from the main repo's index...", "warming up CodeGraph...") and another when it ends ("CodeGraph index synced", "CodeGraph index created", "CodeGraph index seeded from the main repo and synced", "CodeGraph ready"), a warning if it failed or if the sync coordination could not be used at all, or an informational line when it left the run to another session or while its request waits for the index to be free.
- Concurrent rewrites of agent files and `mcp.json` are tolerated (an existing backup is kept, and transient collisions are retried). A per-project lock in the user's temp folder orders the package's own index writers: `codegraph init` and `codegraph sync` of one project take it in turn, so neither starts in the middle of the other. A sync takes the lock for its whole run and records the `codegraph` process it started, so an init cannot begin mid-sync and a session killed mid-sync leaves a lock that still speaks for that process. A session that finds an init holding it skips init, sync and warm-up, and the explorer skips its prefetch; the explorer's prefetch is skipped for an init only, so syncing an existing index does not cost it. When a session exits during init, the package also checks CodeGraph's writer lock. On Windows it conservatively holds the package lock for 60 seconds after spawning the shell, covering the period before CodeGraph writes its own lock. Locks are treated as stale after 11 minutes.
- A separate per-project lease in the same temp folder orders the package's own syncs, startup and compaction alike: a session that finds another one syncing records one pending request on disk and that session serves it with a single follow-up run, so two package-started syncs of one project never run at the same time. A request is only marked as served after the run that started after it has finished, so a session killed mid-sync loses no demand and a session is only told `coalesced` when a run really completed; a request that has not been served yet is reported as `queued` and stays on disk for the next sync. The lease names the session and the `codegraph` process it started, and is restamped before every run: a sync that outlives a killed session keeps the other sessions waiting until it ends, and nothing is killed to get there. When the lease cannot be created or read at all, the package starts no sync (it does not fall back to an uncoordinated one). A session whose startup sync was coalesced still warms the daemon, because the index exists.
- Subagent children and `/reload` do nothing; startup, new, resume and fork do.

After each compaction of a parent session (not of a subagent child, which shares its parent's project) the extension requests one quiet `codegraph sync` in the background, but only when the directory where Pi starts already has an index: a compaction never creates one, never makes the session wait and never shows a message. If the index is being initialised at that moment the request is kept and served once the init ends, instead of being dropped. The outcome — `synced`, `failed`, `coalesced`, `queued` (recorded, not served yet) or a `skipped-` reason (`skipped-no-index`, `skipped-child`, `skipped-coordination-unavailable`) — is appended to `~/.pi/agent/codegraph-subagents/sync.log`, so a sync that failed without telling anyone can still be diagnosed. The coordination above only orders the package's own runs between local sessions of this user that share the temp folder: it cannot order the CodeGraph CLI, a daemon, a git hook, another tool or another machine, and neither a successful exit code nor the prefetch's check makes the index current for a read. See [docs/known-limits.md](docs/known-limits.md).

Before the first change to a file it saves the original next to it as `<file>.pre-codegraph-subagents.bak`; later changes never overwrite that backup.
